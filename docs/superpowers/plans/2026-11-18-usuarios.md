# Usuarios — menú y rol global · Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Añadir a Cantoral una entrada «Usuarios» en «Más» y permitir al administrador cambiar el rol global (`usuario` / `admin`) desde `/admin/perfiles`.

**Architecture:** Se copia la estructura de la pantalla de Usuarios del CRM (`erp-mj`), pero con los componentes y tokens de Cantoral, sin shadcn. La regla que impide que un admin se cambie su propio rol vive en un motor puro con test; la server action la consulta y la RLS (`perfiles_write = es_admin()`) sigue siendo la autoridad. No hay migración.

**Tech Stack:** Next.js 16 (App Router, RSC + server actions), React 19, Supabase (RLS), zod, vitest, Playwright para la verificación.

**Spec:** `docs/superpowers/specs/2026-11-18-usuarios-design.md`

## Global Constraints

- UI en español y tuteo; sin dependencias nuevas; **sin shadcn**.
- Roles globales: `admin` / `usuario` / `externo`. El select solo ofrece `admin` y `usuario`; un `externo` se muestra de solo lectura (ver «Fuera de alcance» del spec).
- Ningún admin puede cambiarse su propio rol.
- La server action re-comprueba permisos; la RLS sigue mandando (PRD §8.3).
- Controles táctiles de 44 px; nada de scroll horizontal a 360 px.
- Commits en español, terminados con `Co-Authored-By: Claude Code <noreply@anthropic.com>`.

## Review Focus

- **El admin se quita a sí mismo el rol** → debe rechazarse con mensaje, no dejar la instalación sin administrador.
- **Invocar la action sin ser admin** (por URL o consola) → mensaje de permiso; la RLS también rechaza.
- **Rol inválido o inyectado** (`externo`, `root`, etc.) → zod lo rechaza antes de tocar la base.
- **Un externo existente** → aparece de solo lectura, sin select. No se puede crear el estado «externo con vínculo» desde la UI; queda anotado como deuda de RLS.
- **El select miente si falla** → al ser controlado por `p.rol`, vuelve al valor del servidor y el error se muestra arriba.

```ts
/**
 * ¿Puede este admin cambiar el rol global de esta cuenta?
 *
 * La única regla es la de no dejar la instalación sin administrador por un
 * clic: nadie se cambia su propio rol. La RLS y la server action vuelven a
 * decidir; esto solo convierte el rechazo en un mensaje.
 */
export function puedeCambiarRol(actorId: string, perfilId: string): Veredicto {
  if (actorId === perfilId) {
    return { ok: false, motivo: 'No puedes cambiarte tu propio rol.' }
  }
  return { ok: true }
}
```

### Task 2: Server action `cambiarRolPerfil`

**Files:**
- Modify: `app/coro/acciones.ts`

**Interfaces:**
- Consumes: `puedeCambiarRol` (Task 1), `obtenerSesion`, `puede`, `Resultado`.
- Produces: `cambiarRolPerfil(raw: unknown): Promise<Resultado>`; entrada `{ perfilId: string (uuid), rol: 'admin' | 'usuario' }`.

- [ ] **Step 1: Add the schema and the action**

En `app/coro/acciones.ts`, añade el import de `puedeCambiarRol` junto al de `puedeVincularse`, y al final del archivo:

```ts
const CambiarRol = z.object({
  perfilId: z.string().uuid(),
  rol: z.enum(['admin', 'usuario']),
})

/**
 * Cambia el rol GLOBAL de una cuenta (admin ↔ usuario).
 *
 * No se puede cambiar el propio: dejaría la instalación sin administrador.
 * La RLS (`perfiles_write = es_admin()`) vuelve a decidir; esto es el mensaje.
 */
export async function cambiarRolPerfil(raw: unknown): Promise<Resultado> {
  const datos = CambiarRol.safeParse(raw)
  if (!datos.success) return { ok: false, error: 'Revisa los datos.' }

  const sesion = await obtenerSesion()
  if (!sesion) return { ok: false, error: 'Tu sesión expiró. Vuelve a entrar.' }
  if (!puede(sesion.sujeto, 'aprobar_perfil')) {
    return { ok: false, error: 'Cambiar el rol de una cuenta es trabajo de un administrador.' }
  }

  const veredicto = puedeCambiarRol(sesion.usuarioId, datos.data.perfilId)
  if (!veredicto.ok) return { ok: false, error: veredicto.motivo }

  const supabase = await createClient()
  const { error } = await supabase
    .from('perfiles')
    .update({ rol: datos.data.rol, updated_at: new Date().toISOString() })
    .eq('id', datos.data.perfilId)

  if (error) return { ok: false, error: 'No pudimos cambiar el rol.' }

  revalidatePath('/admin/perfiles')
  return { ok: true }
}
```
